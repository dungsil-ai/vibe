# 병합 또는 리베이스 충돌 해결

별도로 요청되었거나 caller-owned인 진행 중인 병합 또는 리베이스에 대한 정책. caller-owned 티켓 에이전트는 통합에 이 과정을 사용하지 않는다. 통합은 호출자가 소유한다. Standalone 완료는 자동으로 병합을 시작하지 않는다.

1. **작업과 범위를 정한다.** 현재 병합 또는 리베이스 상태, 관련 이력, 모든 충돌 파일을 조사한다. 주된 의도를 커밋 메시지, 풀 리퀘스트, 원래 티켓까지 추적한다. 편집 전에 의도한 작업과 정확한 대상 경로를 명시한다.

2. **안전하지 않거나 모호한 상태에서 멈춘다.** 관련 없는 tracked 또는 untracked 변경(사용자 파일이나 비밀 파일 포함)이 나타나거나, 주된 의도가 불명확하면 자동 통합을 멈추고 상태를 보고한다. 해결을 추측하거나, 전체를 스테이지하거나, 사용자 상태를 정리·버리거나, 강제로 계속하거나, 사용자·비밀 파일을 포함하지 않는다. 작업이 안전하게 끝날 수 없을 때는 원본과 결과 브랜치와 커밋을 보존한다.

3. **명확하게 확정된 의도만 해결한다.** 이름 붙인 각 대상 경로에 대해 양쪽에서 호환되는 확정된 의도를 유지한다. 의도가 양립할 수 없을 때는 문서화된 병합 목표에 맞는 동작만 선택하고 트레이드오프를 기록한다. 동작을 새로 만들지 않는다.

4. **이름 붙인 대상 경로만 스테이지한다.** 이 작업에서 해결된 정확한 대상 경로만 스테이지한다. `git add -A`, 관련 없는 파일, 사용자 파일, 비밀 파일은 절대 사용하지 않는다.

5. **검사하고 의도한 작업을 마친다.** 프로젝트의 관련 검사를 실행한다. 1단계에서 조사한 작업(병합이면 `git merge --continue`, 리베이스면 `git rebase --continue`)만, 그리고 그 검사를 통과한 뒤에만 계속한다. 새 충돌, 안전하지 않은 상태, 불확실성이 나타나면 강제로 계속하지 말고 멈추고 보고한다. 원본과 결과 브랜치와 커밋을 보존한다.
