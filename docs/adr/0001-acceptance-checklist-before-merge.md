# 인수 체크리스트는 머지 전에 켠다

호스티드 트래커에서 인수 체크리스트와 이슈 닫기를 한 묶음으로 머지 반영 뒤에 두면, 사람이 머지 여부를 판단할 때 체크리스트를 쓸 수 없다. 머지는 사람이 하고 에이전트는 하지 않으므로, `/vibe-implement`는 깨끗한 검토 뒤 PR/MR 게시 또는 호출자 반환 전에 인수 체크박스를 켠다. `/vibe-review`는 읽기 전용이며 그 쓰기를 머지 후로 미루지 않는다. 이슈 닫기는 체크리스트와 별개다. 자격 있는 standalone 닫기(PR/MR target이 provider default 브랜치이고 머지로 인수가 끝나는 정확한 구현 티켓 하나)는 provider-native 닫기 참조로 PR/MR 게시 시 연결되어, 사람이 UI에서 머지하는 행위와 함께 원자적으로 닫힌다. 그 닫기는 머지 승인 자체가 승인이며 별도 미리보기나 승인을 요구하지 않는다. 자격이 없는 닫기(non-default target, 남는 운영·배포 게이트, 부모·다중 목표 모호성)는 반영 증거와 별도 승인이 있을 때만 제안한다.

## 검토한 선택

- **머지 반영 뒤에 체크리스트와 닫기를 함께 갱신** — 이슈가 머지되지 않은 작업을 완료로 보이게 하는 것은 막지만, 머지 게이트와 완료 기록을 섞는다. 기각.
- **MR 본문에만 인수 체크리스트를 두고 이슈 체크박스는 머지 뒤에 켠다** — 이슈 체크리스트를 머지 판단에 쓰지 못하게 한다. 기각.
- **머지 전에 체크리스트를 켜고, 닫기는 머지와 원자적으로 연결한다** — 자격 있는 standalone 티켓은 게시 시 닫기 참조를 넣어 사람의 UI 머지가 닫기 승인이 되게 한다. 머지 후 별도 왕복, 미리보기, 승인이 필요 없다. 자격이 없으면 닫기 키워드 없는 참조만 두고 반영 증거와 별도 승인을 요구한다. 채택.
- **자격 있는 닫기를 게시 뒤 재개에서 반영 증거와 별도 승인으로 처리한다** — 자격 있는 경우 항상 게시 후 재개 왕복과 중복 승인을 부과한다. 사람이 UI에서 머지하는 행위 자체가 닫기 승인인데도. 기각.
