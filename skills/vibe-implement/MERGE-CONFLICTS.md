# 병합 또는 리베이스 충돌 해결

이 문서는 사용자가 별도로 요청했거나 호출자가 소유한 진행 중인 병합 또는 리베이스에 적용하는 정책이다. 호출자가 소유한 티켓을 맡은 에이전트는 통합에 이 절차를 사용하지 않는다. 통합은 호출자가 소유한다. standalone 완료는 자동으로 병합을 시작하지 않는다.

1. **작업과 범위를 정한다.**
   1. 진행 중인 병합 또는 리베이스의 상태와 커밋 이력을 조사한다. 충돌한 모든 파일도 확인한다.
   2. 주된 의도를 커밋 메시지, 풀 리퀘스트, 원래 티켓까지 추적한다.
   3. 편집 전에 의도한 작업과 정확한 대상 경로를 명시한다.
2. **안전하지 않거나 모호한 상태에서 멈춘다.**
   1. 대상 경로 밖에 추적 중인 변경이나 추적하지 않는 파일이 있으면 자동 통합을 멈춘다.
   2. 주된 의도가 불명확하면 자동 통합을 멈춘다.
   3. 멈춘 이유와 상태를 사용자에게 보고한다.
   - 충돌 해결 방법을 추측하지 않는다.
   - 모든 파일을 스테이지하지 않는다.
   - 사용자 상태를 정리하거나 버리지 않는다.
   - 강제로 계속하지 않는다.
   - 사용자 파일이나 비밀 파일을 작업에 포함하지 않는다.
   - 작업을 안전하게 마칠 수 없으면 원본 브랜치, 결과 브랜치, 커밋을 보존한다.
3. **명확하게 확정된 의도만 해결한다.**
   1. 이름 붙인 각 대상 경로에서 양쪽의 확정된 의도가 호환되면 그 의도를 유지한다.
   2. 의도가 양립하지 않으면 문서화된 병합 목표에 맞는 동작만 선택한다.
   3. 선택의 득실을 기록한다.
   - 새 동작을 만들지 않는다.
4. **이름 붙인 대상 경로만 스테이지한다.**
   1. 이번 작업에서 이름 붙이고 해결한 정확한 대상 경로만 스테이지한다.
   - `git add -A`를 사용하지 않는다.
   - 이름을 붙인 대상 경로 밖의 파일, 사용자 파일, 비밀 파일은 스테이지하지 않는다.
5. **검사하고 의도한 작업을 마친다.**
   1. 프로젝트에서 이 작업에 필요한 검사를 실행한다.
   2. 검사를 통과한 뒤에만 1단계에서 조사한 작업을 계속한다.
      - 병합이면 `git merge --continue`를 실행한다.
      - 리베이스면 `git rebase --continue`를 실행한다.
   3. 새 충돌, 안전하지 않은 상태나 불확실성이 나타나면 강제로 계속하지 말고 멈춘다.
   4. 중단 이유와 근거를 사용자에게 보고한다.
   5. 원본 브랜치, 결과 브랜치, 커밋을 보존한다.
