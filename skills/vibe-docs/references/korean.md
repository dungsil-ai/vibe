# 한국어 작성 지침

한국어 글은 이 파일의 규칙으로 쓰고 검토한다. 목표는 읽는 사람이 한 번 읽고 뜻을 정확하게 이해한 뒤 다음 행동을 정하는 것이다. 짧게 쓰는 것은 목표가 아니라 수단이므로, 판단에 필요한 근거를 지우면서까지 줄이지 않는다.

괄호 안의 숫자는 한국어 통제 언어 규격 STE-KO의 규칙 번호다. 전체 규칙과 근거는 `references/korean/writing-rules.md`에, 비승인 표현과 대체어는 `references/korean/substitutions.md`에 있다. 경로는 모두 이 스킬 디렉터리를 기준으로 한다.

## 적용 범위

- 한국어로 쓰는 문장에 적용한다. 외국어 문장이나 어휘를 한국어로 번역하거나 바꾸라는 규칙이 아니다.
- 코드 주석과 커밋 메시지의 한국어 문장에도 적용한다. 코드, 변수명, 로그 문자열, 인용문은 바꾸지 않고 프로젝트의 기존 관례를 따른다.
- 사용자의 말투와 어휘를 따라 하지 않는다. 사용자가 어떻게 쓰든 이 규칙을 똑같이 적용한다.
- 서브에이전트에게 줄 프롬프트를 한국어로 썼다면, 서브에이전트를 호출하기 전에 이 규칙으로 검토한다. 서브에이전트가 낸 결과를 사용자에게 전할 때에도 이 규칙을 적용한다.

## 표면

STE-KO는 글이 놓이는 자리를 표면이라고 부르고, 표면마다 문장과 문단의 상한을 다르게 정한다. 결과물의 표면은 아래 표에서 고른다.

| 결과물 | 표면 | 문장 상한 | 문단 상한 |
| --- | --- | --- | --- |
| 스킬 파일과 문서 | `문서` | 25어절 | 6문장 |
| 이슈 제목과 본문 | `문서` | 25어절 | 6문장 |
| 코드 주석 | `코딩` | 20어절 | 4문장 |
| 커밋 메시지 | `코딩` | 20어절 | 4문장 |
| PR 제목과 본문 | `코딩` | 20어절 | 4문장 |
| 이슈 댓글, PR 리뷰와 댓글 | `대화` | 25어절 | 4문장 |

어절은 띄어쓰기 단위로 센다. 상한을 넘으면 문장을 나누고, 조사를 빼서 줄이지 않는다. 모든 표면을 9장의 `표준` 등급으로 쓴다. 10.1이 `대화`와 `코딩` 표면의 기본값으로 정한 `압축` 등급은 쓰지 않는다.

## 내용

1. **결론을 먼저 쓴다.** 첫 문장이나 두 번째 문장 안에 결론과 현재 상태가 나와야 한다. 조사 과정과 배경은 그다음에 쓴다. (6.1)
2. **상대의 글을 되풀이하며 시작하지 않는다.** 답변과 리뷰를 `좋은 질문입니다`, `말씀하신 대로`, `확인해 보겠습니다`로 열지 않는다. (10.4)
3. **사실, 추론, 미확인을 구분한다.** 확인한 사실은 `-했다`로, 추론은 `-로 보인다`와 근거로, 확인하지 못한 것은 `아직 확인하지 못했다`로 쓴다. `-인 것 같습니다`는 세 상태 중 어느 것인지 알 수 없으므로 쓰지 않는다. (3.7, 6.2)
4. **모르면 첫 문장에서 모른다고 쓴다.** 확인하지 못한 것을 글 뒤쪽에 숨기지 않는다. (10.5)
5. **실행하지 않은 검사를 통과했다고 쓰지 않는다.** 실행한 검사와 실행하지 않은 검사를 나눠서 쓴다. 빌드, 배포, 마이그레이션도 같다. (10.8)
6. **되묻기는 한 번에 하나만 한다.** 선택지는 3개까지 준다. 선택지가 더 많으면 하나를 추천하고 이유를 한 줄로 쓴다. (10.3)

## 문장

1. **한 문장에는 뜻을 하나만 담는다.** `그리고`로 이을 수 있으면 두 문장으로 나눈다. 연결어미로 절을 3개 넘게 잇지 않는다. (4.2, 4.3)
2. **뜻을 담은 문장 성분을 빼지 않는다.** 읽는 사람이 대상과 범위를 짐작하지 않도록 맥락과 정보를 충분히 쓴다. [`그러면 경고가 붙습니다.` → `그러면 이미 작업 중인 파일에도 경고 표지가 붙습니다.`]
3. **조사와 어미를 생략하지 않는다.** 대비를 나타낼 때는 `-은/는`, 새 정보를 나타낼 때는 `-이/가`를 쓴다. 부사, 보조사, 선어말어미, 보조 용언은 뜻을 분명하게 할 때 쓰고, 대응표에 있는 모호한 부사는 쓰지 않는다. [`이 결정은 이후 중요 정책이 갈리는 자리. 컨텍스트 압축 전 신중 반영한다.` → `이 결정은 이후의 중요한 정책에도 영향을 주므로, 컨텍스트가 압축되기 전에 미리 반영해 두겠습니다.`] (4.6)
4. **서술어와 종결어미로 문장을 끝낸다.** 명사구, 부사구, 연결어미로 문장을 끝내지 않는다. `고침`, `막혔음` 같은 명사형 종결도 쓰지 않는다. 제목과 목록 항목에는 이 규칙을 강제하지 않는다. (9.1)
5. **명사를 조사 없이 4개 이상 잇지 않는다.** 조사, 어미, 관형절로 명사 사이의 관계를 밝힌다. 이때 `-의`를 필요 이상으로 쓰면 뜻을 담은 성분이 빠지기 쉽다. [`인증 토큰 갱신 실패 처리` → `인증 토큰 갱신이 실패했을 때 실행하는 코드`, `사본의 문구는 작업의 상황을` → `사본에 적힌 문구는 작업이 진행되는 상황을`] (2.1, 2.2)
6. **능동문으로 쓰고 행위자를 밝힌다.** `처리되었습니다`가 아니라 `서버가 요청을 처리했다`처럼 누가 무엇을 했는지 쓴다. 이중피동도 쓰지 않으므로 `보여집니다`는 `보입니다`로, `되어집니다`는 `됩니다`로 쓴다. (3.1, 3.2, 3.3)
7. **문장 길이와 종결어미를 섞는다.** 같은 종결어미를 세 문장 연속 쓰지 않는다. 세 항목 나열을 습관으로 쓰지 않고, 항목이 둘이면 둘로, 넷이면 넷으로 쓴다. (4.8)
8. **지시문의 종결어미를 통일한다.** `-하십시오`와 `-한다` 가운데 하나를 골라 쓰고, `-하시면 됩니다`, `-하는 것이 좋습니다`는 쓰지 않는다. `문서`와 `대화` 표면은 글 하나 안에서, `코딩` 표면은 저장소 안에서 통일한다. (5.2, 10.2)

## 어휘

1. **비승인 표현을 쓰지 않는다.** `references/korean/substitutions.md`의 비승인 표현은 승인 표현으로 바꾼다. 번역투 조사, 이중피동, 빈 동사, 공문투 한자어, 모호어, 접미사 남용, 대화 군더더기, 수치와 기간 표기, 외래어 표기가 이 목록에 있다. (1.3)
2. **뜻이 같으면 쉬운 말을 쓰고, 뜻이 흐려지면 정확한 한자어를 쓴다.** 쉬운 말로 바꿔도 뜻과 정확도가 같으면 쉬운 말을 고른다. 쉬운 말로 바꾸면 뜻이 흐려질 때만 맥락에 맞는 한자어를 고르고, 조사와 어미를 붙여 어휘 사이의 관계를 드러낸다. [`쓴 비용을 구하는 토큰 카운트 함수에 문제가 생기면`은 맥락에 맞는 어휘를 쓰지 않아 뜻이 부족하다. `지출 비용 추론 용도의 토큰 카운트 함수의 오류 상황에서`는 조사와 어미가 없어 관계가 흐리다. → `지출한 비용을 추론하는 토큰 카운트 함수에 오류가 발생하면`] (1.6)
3. **비유와 관용구를 쓰지 않는다.** 일반적인 명사와 동사를 쓸 자리에 비유, 관용구, 의성어, 의태어를 쓰지 않는다. `병목`, `메모리 누수`처럼 기술 용어로 굳은 말은 비유로 보지 않는다. [`서버가 뻗었다` → `서버가 응답을 멈췄다`, `분석의 흐름` → `분석의 방향`, `코드로 박는 자리` → `코드에 명시하는 작업`, `요청을 받습니다` → `요청대로 설정 파일을 고치겠습니다`] (1.8)
4. **한 대상은 항상 같은 단어로 부른다.** 지루해 보인다는 이유로 동의어를 바꿔 쓰지 않는다. 한 단어는 한 글 안에서 한 가지 뜻으로만 쓴다. (1.1, 1.2)
5. **고유 명사와 기술 용어는 널리 쓰는 표기를 따른다.** 널리 쓰는 번역어나 음차가 있으면 그 표기를 쓰고, 없으면 원어를 쓴다. 함수명, 명령어, 파일 경로, 오류 클래스, HTTP 상태 코드 같은 식별자는 번역하지 않고 코드 서식으로 감싼다. 약어는 처음 나올 때 한 번만 풀어 쓴다. (1.4, 1.5)
6. **확정된 도메인 용어와 기술 용어는 대응표 검사에서 뺀다.** `SKILL.md`의 `확정된 도메인 용어 보호`에 속하는 용어와 식별자는 대응표에 있어도 그대로 쓴다. 트래커 항목을 가리키는 `이슈`는 대응표 E절의 `이슈`와 다른 말이다. E절의 `이슈`는 문제나 장애를 흐리게 부르는 말이다. (1.4)

## 문장부호

- 범위에 물결표를 쓰지 않는다. 마크다운은 `3~5개`의 물결표를 취소선으로 읽으므로 `3-5개`로 쓴다. (8.1)
- 엠대시(`—`)를 쓰지 않는다. 엠대시는 앞뒤 문장의 관계를 지나치게 함축하므로, 문맥과 형식에 맞게 콜론이나 접속사로 바꾼다. `references/korean/` 파일의 문장에 엠대시가 있어도 따라 쓰지 않는다.
- 괄호 안에 괄호를 넣지 않는다. `/`를 `그리고`나 `또는`의 뜻으로 쓰지 않는다. 말줄임표로 문장을 끝내지 않는다. (8.2, 8.4, 8.5)

## 표면별 규칙

### `대화` 표면

- 분량은 판단에 필요한 만큼 정한다. 단순한 사실이나 상태는 1-3문장으로, 설명이나 추천은 결론과 근거 2-4개로 쓴다. 원인 진단이나 중요한 결정은 결론, 근거, 영향, 다음 행동 순서로 쓴다. (10.15)
- 다음 행동으로 끝낸다. 상태만 알리고 끝내지 않는다. (10.16)
- 두 문장짜리 답에 제목을 붙이지 않는다. 같은 결론을 요약, 본문, 마무리에서 되풀이하지 않는다. (10.17)

> 나쁨: "말씀하신 배포 실패 건을 확인해 달라는 요청으로 이해했습니다. 확인 결과, 인증서 부분에서 문제가 발생된 것으로 보여집니다."
> 좋음: "인증서가 8월 14일에 만료됐습니다. 자동 갱신이 6월부터 꺼져 있었습니다. 인증서를 갱신하고 다시 배포하십시오."

### `코딩` 표면

- 무엇을 왜 바꿨는지 쓴다. 어떻게 바꿨는지는 코드가 말한다. (10.6)
- 위치는 `파일:줄`로 쓴다. `인증 부분`이나 `그 함수`라고 쓰지 않는다. (10.7)
- 작업을 끝냈다고 알릴 때는 건너뛴 것, 실패한 것, 다음 사람이 할 것을 함께 쓴다. (10.9)

> 나쁨: "리팩터링 및 코드 정리. 테스트도 추가했고 전부 통과합니다."
> 좋음: "토큰 만료 검사를 `<`에서 `<=`로 고쳤다. 만료 당일 로그인이 막혔다. 테스트 3개를 추가했고 아직 실행하지 않았다."

## 지우는 것

- 인사말, 자기 서술, 완충어를 지운다. `확인해 보겠습니다`를 쓰지 않고 결과를 바로 쓴다. (9.2)
- 장식용 표와 이모지를 지운다. 표는 항목이 3개를 넘고 열이 2개를 넘을 때만 쓴다. (9.2)
- 갈래가 둘 이상인 내용은 목록으로 쓰고, 한 줄 논지는 산문으로 쓴다. 목록이 필요한 자리에서 산문을 고집하지 않는다.
- 로그와 오류 출력을 통째로 붙이지 않는다. 판단을 가르는 한 줄만 인용한다. (9.2)

## 지우지 않는 것

분량을 줄일 때도 아래 내용은 남긴다. (9.3)

- 부정과 한정을 나타내는 말: `안`, `못`, `없다`, `아니다`, `만`, `-뿐`, `제외`
- 안전 경고와 되돌릴 수 없다는 사실
- 수치, 단위, 기준 시점
- 사실, 추론, 미확인의 구분
- 실패, 부분 성공, 건너뛴 단계
- 고유 식별자, 코드, 오류 메시지 원문

## 업무 항목

저장소나 호출한 스킬이 트래커 항목의 템플릿을 정했다면 그 템플릿을 따른다. 템플릿이 없을 때만 `references/korean/tasks.md`의 틀로 제목, 이유, 완료 기준, 다음 행동을 쓴다.

## 검토

다음 글은 검토를 통과하지 못한 것이다.

- 일반 한국어 문장에 뜻을 숨기는 불필요한 영어 표현이 남아 있다.
- 조사, 서술어, 문장 끝이 빠져 뜻이 끊긴다.
- 제목이나 목록이 한국어와 영어 명사를 어색하게 이어 붙인 형태다.

검토 결과에는 `어색하다` 대신 어긴 규칙 번호와 근거를 함께 쓴다. `2.1 위반: 명사 5개를 조사 없이 이었다.`가 그 예다. 번호와 근거가 함께 있으면 고칠 방향이 하나로 정해진다.

## 검사

한국어 최종본은 아래 순서로 검사한다.

1. 커밋 메시지, PR 본문, 댓글처럼 파일이 아닌 글은 UTF-8 임시 파일에 저장한다. 코드 주석은 주석 기호(`//`, `#`, `/*`, `*`)와 주석 태그를 뺀 문장만 옮긴다. 검사기는 네 칸 이상 들여 쓴 줄을 코드로 보고 건너뛴다.
2. 아래 명령을 실행한다. `<표면>`에는 위 `표면` 표에서 고른 값을 넣는다.

   ```bash
   python3 scripts/korean/check.py --surface <표면> <file>
   ```

3. 검사기가 보고한 위반을 고치고, 위반이 없을 때까지 다시 실행한다. 검사기가 확정된 도메인 용어나 기술 용어를 비승인 어휘로 보고하면 `어휘` 6번에 따라 그대로 둔다.

검사기는 규칙 8개만 본다. 4.1, 4.7, 4.8, 3.2, 8.1, 8.5, 1.3과 `대화` 표면의 10.4다. 나머지 규칙은 `references/korean/writing-rules.md` 부록 A 점검표로 직접 확인한다.
