# 프로토타입 티켓

`유형:프로토타입` 티켓은 아래 방식으로 해결한다. 프로토타입은 사람 참여형 human-in-the-loop(HITL) 유형이다. 산출물은 사람이 구체적으로 반응할 대상을 제공한다. 사용자가 참여하는 대화에서 결정을 검증할 때만 티켓을 해결한다.

프로토타입은 **질문에 답하기 위한 일회용 코드**다. 질문이 형태를 결정한다.

## 분기 고르기

어떤 질문에 답하고 있는지 확인한다. 사용자 프롬프트, 주변 코드, 또는 사용자가 곁에 있으면 직접 묻는다:

- **"이 로직/상태 모델이 맞는 느낌인가?"** 이 질문은 [PROTOTYPE-LOGIC.md](PROTOTYPE-LOGIC.md)에서 다룬다. 상태 기계를 종이 위에서는 생각하기 어려운 사례로 밀어보는 작은 대화형 터미널 앱을 만든다.
- **"이건 어떤 모양이어야 할까?"** 이 질문은 [PROTOTYPE-UI.md](PROTOTYPE-UI.md)에서 다룬다. `.agents/prototype/<name>/` 아래의 로컬 라우트나 진입점에 근본적으로 다른 UI 변형 여럿을 만든다. URL 검색 매개변수와 하단 플로팅 바로 UI 변형을 전환한다.

두 분기는 산출물이 다르다. 잘못 고르면 프로토타입 전체가 헛일이 된다. 질문이 정말 모호하고 사용자에게 물을 수 없으면 주변 코드에 더 잘 맞는 분기를 고른다. 백엔드 모듈이면 로직 분기를, 페이지나 컴포넌트면 UI 분기를 고른다. 선택한 가정을 프로토타입 맨 위에 적는다.

## 양쪽에 공통인 규칙

1. **코드보다 먼저 격리.** 코드를 쓰기 전에 `.agents/prototype/<name>/`을 만든다. 모든 산출물을 그 안에 둔다: 소스, 의존성 매니페스트와 락파일, fixture, 스크래치 데이터, 라우트 설정, 실행 안내. 프로덕션 소스는 배경을 파악하려고 읽기 전용으로만 참고할 수 있다. 절대 가져오지 않는다.
2. **프로덕션 영향 없음.** 프로덕션 소스나 모듈을 수정하거나 가져오지 않고, 루트 매니페스트, 작업 실행기, 라우트, 설정, 공유 컴포넌트를 편집하지 않고, 실제 인증을 사용하거나 실제 데이터를 변경하지 않는다. 프로토타입 로컬 의존성과 로컬 복사본 또는 대용품을 사용한다.
3. **실행 명령 하나 문서화.** `.agents/prototype/<name>/` 안에 프로젝트 수준 변경 없이 그 디렉터리에서 프로토타입을 시작하는 명령 하나를 문서화한다.
4. **영속성은 쓰지 않는다.** 상태는 메모리에 둔다. 질문이 영속성을 명시적으로 다루면 `.agents/prototype/<name>/` 안에 이름이 명확하고 지울 수 있는 스크래치 DB나 로컬 파일을 사용한다.
5. **다듬기 건너뛰기.** 테스트를 추가하지 않는다. 프로토타입을 실행할 수 있게 하는 데 필요한 오류 처리만 추가한다. 추상화를 추가하지 않는다. 빠르게 배우는 것이 목적이다.
6. **상태 드러내기.** 로직 동작이나 UI 변형을 전환할 때마다 상태 전체를 출력하거나 렌더링해 변경을 보여준다.
7. **구현하지 말고 기록.** 사용자가 참여하는 HITL 교환이 결정을 검증한 뒤, 프로토타입 디렉터리 전체를 **1차 출처**로 일회용 브랜치에, main 밖에 캡처하고 판결을 기록한다. 프로덕션에 구현하지 않는다. 그건 별도 후속 티켓이다.

## 지도와 다시 연결하기

프로토타입은 정답이 아니라 **자산**이다. 티켓에서 링크한다. 본문에 붙여 넣지 않는다.

- `.agents/prototype/<name>/`을 **1차 출처**로 일회용 브랜치에, main 밖에 커밋하고, 그 브랜치에 연결되는 맥락 포인터를 티켓에 남긴다.
- 판결(어떤 형태가 이겼고 왜인지)을 티켓의 **해결 댓글**로 올린다. 티켓을 닫는다. 한 줄 gist와 링크를 지도의 **Decisions so far**에 추가한다. 이 해결 중에 프로토타입을 프로덕션에 접지 않는다. 프로덕션 구현은 별도 후속 티켓이다.
- 지도는 결정을 기록하고, 브랜치는 프로토타입을 1차 출처로 보존한다.
