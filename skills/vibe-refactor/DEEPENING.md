# 심화

얕은 모듈 묶음을 의존성을 고려해 안전하게 깊게 만드는 방법을 설명한다. [VOCABULARY.md](VOCABULARY.md)의 용어(**모듈**, **인터페이스**, **경계**, **어댑터**)를 쓴다. 사용자에게 보이는 글에도 그 용어를 쓴다. `seam`을 쓰지 않는다.

## 의존성 분류

심화 후보를 평가할 때 의존성을 분류한다. 분류에 따라 깊어진 모듈을 경계 너머에서 어떻게 테스트하는지가 결정된다.

### 1. 프로세스 안

이 분류에는 순수 계산과 메모리 상태만 있고 I/O는 없다. 이런 모듈은 항상 깊게 만들 수 있다. 모듈을 합치고 새 인터페이스로 직접 테스트한다. 어댑터는 필요하지 않다.

### 2. 로컬 대체

로컬 테스트 대역이 있는 의존성(Postgres 대신 PGLite, 메모리 파일 시스템). 대역이 있으면 깊게 만들 수 있다. 깊어진 모듈은 테스트에서 대역을 돌리며 테스트한다. 경계는 안쪽이며, 바깥 인터페이스에 포트를 두지 않는다.

### 3. 소유한 원격 (포트와 어댑터)

이 분류는 네트워크 너머의 자체 서비스(마이크로서비스, 내부 API)를 다룬다. 경계에 **포트**(인터페이스)를 정의한다. 깊은 모듈에 로직을 두고, 전송은 **어댑터**에 둔다. 테스트에서는 메모리 어댑터를 쓰고, 프로덕션에서는 HTTP, gRPC, 큐 어댑터를 쓴다.

권고: *"경계에 포트를 두고, 프로덕션은 HTTP 어댑터, 테스트는 메모리 어댑터로 구현하라. 네트워크로 나뉘어 배포돼도 로직은 깊은 모듈 하나에 둔다."*

### 4. 완전한 외부 (모의)

제어하지 못하는 Stripe나 Twilio 같은 제3자 서비스를 다룬다. 깊어진 모듈은 주입된 포트로 외부 의존성을 받는다. 테스트에서는 모의 어댑터를 쓴다.

## 경계 규칙

- **"어댑터가 하나면 경계를 만들지 마라"**. 어댑터가 둘일 때(보통 프로덕션과 테스트)만 경계에 포트를 둔다. 어댑터 하나짜리 경계는 호출이 한 번 더 필요한 불필요한 계층이다.
- **안쪽 경계와 바깥 경계.** 깊은 모듈은 공개 바깥 경계 외에, 자기 테스트만 쓰는 안쪽 경계를 가질 수 있다. 테스트가 안쪽 경계를 사용해도 공개 인터페이스로 노출하지 않는다.

## 테스트 전략: 덧씌우지 말고 교체하라

- 얕은 모듈의 기존 단위 테스트는 깊어진 모듈의 인터페이스 테스트가 생기면 지워라.
- 깊어진 모듈의 인터페이스에 새 테스트를 작성한다. **테스트는 인터페이스를 통해서만 모듈에 닿는다.**
- 테스트는 내부 상태가 아니라 인터페이스로 보이는 결과를 검증한다.
- 테스트는 구현을 바꿔도 계속 통과해야 한다. 구현이 바뀔 때 테스트도 바꿔야 한다면 인터페이스 너머를 테스트하는 것이다.
