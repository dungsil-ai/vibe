# 설정 문서와 기본값

`AGENTS.md`의 스킬 설정 블록이나 `docs/agents/` 설정 문서가 없어도 초기화는 선행 조건이 아니다. 기존 설정이나 사용자가 트래커를 따로 지정하지 않았다면 **로컬 Markdown**으로 바로 진행한다. GitHub·GitLab remote가 있다는 이유만으로 원격 트래커를 선택하지 않는다.

## 설정 해석

- 사용자 지시와 이미 기록된 트래커·경로·라벨·도메인 문서 설정을 우선한다. 설정 파일 중 없는 파일이 있으면 있는 설정은 유지하고, 빠진 항목에만 아래 기본값을 쓴다.
- `docs/agents/issue-tracker.md`가 없고 다른 명시적 선택도 없으면 [로컬 트래커 규칙](issue-tracker-local.md)을 읽는다. 명세는 `.agents/plans/<feature>/spec.md`, 구현 티켓은 같은 디렉터리의 `issues/<NN>-<slug>.md`에 둔다. 결정 지도와 유형별 기록에는 로컬 트래커 규칙 문서의 경로와 상태 규칙을 적용한다.
- `docs/agents/triage-labels.md`가 없으면 [기본 역할 매핑](triage-labels.md)을 읽는다. 로컬 작업에서는 역할을 Markdown 기록에 적고 원격 라벨은 만들지 않는다. 기존 한국어 문자열과 `Type:`·`Status:` 계약을 그대로 유지한다.
- `docs/agents/domain.md`가 없으면 [기본 도메인 문서 규칙](domain.md)을 읽는다. 기존 `CONTEXT.md`, `CONTEXT-MAP.md`와 주제를 다루는 아키텍처 결정 기록(ADR)을 사용한다. 이 자료가 모두 없으면 미리 만들라고 요구하지 않는다.

이후 스킬이 위 설정 경로를 읽으라고 할 때도 같은 대체 문서를 사용한다. 내장 참고 문서는 읽기만 하며 프로젝트로 복사하지 않는다. 원격 트래커가 명시되어 있으면 로컬로 바꾸지 않고 [GitHub](issue-tracker-github.md) 또는 [GitLab](issue-tracker-gitlab.md) 참고 문서와 주어진 저장소 정보를 사용한다. 다른 트래커에 필요한 정보가 빠졌다면 그 정보만 확인하고 초기화 전체를 요구하지 않는다.

## 권한과 산출물

다음 경우에는 `/vibe-plan`의 [실행 계획 계약](../../vibe-plan/EXECUTION-PLAN.md)을 따른다:
- 명시적으로 `plan`, `review-plan`, `reconcile`을 실행할 때
- 감사나 방향 조사에서 선택한 항목의 실행 계획을 인계할 때

이 경로는 로컬 계획을 원본으로 유지한다. `--issues`가 있을 때만 그 계약에 따라 GitHub에 게시한다. 일반 명세나 티켓의 기존 트래커 설정을 바꾸지 않는다. 기존 설정과 게시 대상이 충돌하면 어느 쪽을 따를지 사용자에게 먼저 묻는다.

설정이 없다는 이유만으로 `/vibe-init`을 호출하거나 실행을 요구하지 않는다. 기본값을 적용하려고 `AGENTS.md`나 `docs/agents/` 설정 파일을 만들지 않고, 초기화만 하려고 커밋하거나 `push`하지도 않는다. `/vibe-init`은 사용자가 설정을 만들거나 바꾸라고 요청했을 때만 실행한다.

로컬 기본값은 쓰기 권한을 추가하지 않는다. 계획 스킬은 요청 범위의 계획 파일을 만들고, 구현 스킬은 기존 완료 계약에 따라 티켓을 갱신한다. 리뷰는 기존 로컬 명세·티켓을 읽기만 한다. 설정이 없다는 이유로 기존 산출물을 이동하거나 원격 이슈·PR/MR을 만들지 않는다.
